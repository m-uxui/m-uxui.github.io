계획과 실제 여행의 단절

여행 일정은 PC에서 계획하고 실제 여행에서는 모바일 지도와 별도 예약 정보를 확인하는 등 여러 서비스를 오가야 함

PC–Mobile 여행 경험 연결

PC에서는 일정과 지도를 나란히 놓아 전체 여정을 계획하고, Mobile에서는 일정 목록과 지도 모드로 이동 정보를 확인하도록 디바이스별 화면을 나누면서 하나의 여행 데이터로 연결

02

일정 편집의 번거로움

장소를 추가한 뒤 날짜와 순서를 변경하려면 반복적인 입력과 수정이 필요함

장소 추가 → 순서 변경 → 거리 확인 → 여정 완성

Drag & Drop 기반 여정 편집

03

예약·이동·기록 정보의 분산

예약 정보는 바우처에, 이동 정보는 지도에, 여행 경비는 별도의 가계부에 흩어져 있음

각각의 정보를 별도로 관리하지 않고 다음 여행 행동으로 연결

여행 데이터를 다음 행동으로 연결

Voucher → Schedule  예약 서류를 해당 일정에 첨부해 연결

Receipt → Expense  영수증을 모아 여행 경비로 기록

퍼소나 & 여정

김여행 · 자유여행자

여행 전에 여러 장소와 예약 정보를 정리하고 여행 중에는 오늘의 일정과 이동 경로를 빠르게 확인하고 싶은 사용자

왜 힘든가

여행 일정, 지도, 예약 바우처, 경비가 서로 다른 서비스에 흩어져 있어 여행 전에는 정보를 모으고 여행 중에는 다시 찾아야 함

무엇을 원하는가

PC에서 여행 전체를 한눈에 계획하고 장소의 순서를 쉽게 바꾸면서 실제 이동 가능한 여정을 만들고 싶음

무엇이면 만족하는가

예약한 바우처가 일정에 연결되어 한곳에 보관되고, 여행 중에는 Mobile에서 일정과 이동 정보를 바로 확인하며 여행 후에는 모아둔 영수증으로 경비까지 정리할 수 있는 경험

그래서, 여행자의 여정은 이렇게 이어집니다

MVP 정의

검증하려는 가설 · 여행자는 “하루 단위 일정 + 지도 + 기록”이 하나로 이어지면, 여러 앱을 오가지 않고 여행 하나를 끝까지 이 서비스에서 관리한다.

MVP — 반드시 있어야 하는 것

1. 구글·카카오 로그인
2. 여행 만들기(목적지·기간)
3. 일차별 일정 추가·수정·삭제·순서 변경
4. 장소 검색과 일정 담기
5. 지도 경로와 장소 간 이동 거리·시간
6. 가계부(지출 기록, 여행지 통화 → 원화)
7. 일정에 사진·파일 첨부, 보관함에서 모아 보기
8. 여행 정보(환율·시차·날씨)

검증 기준 (목표)

· 여행 1건을 앱 안에서 처음부터 끝까지 만들 수 있다
· 장소 검색 후 일정에 담기까지 3번 안에 끝난다
· 여행을 열 때 “불러오는 중” 대기가 보이지 않는다
· 모바일(iPhone)에서 한 손으로 조작할 수 있다
· 여행 중 필요한 서류·영수증을 앱에서 다시 찾을 수 있다

MVP 이후 확장

· AI 추천 일정(도시·일수·관심사 기반 초안)
· 구글 지도 저장 목록(CSV) 가져오기
· 영수증 사진으로 지출 자동 입력
· 여행 공유 링크
· 다녀온 여행 표지(앨범 경험)
· 가입자 통계(관리자)

Why Different

이런 점이 다릅니다

"기능이 많은 앱"이 아니라 "여행 중에 손이 덜 가는 앱"을 목표로 설계

나라에 맞는 지도로 자동 연결

국내 장소는 네이버 지도, 해외 장소는 구글 지도로 바로 연결
사용자는 어느 앱을 열지 고민하지 않도록 설계

한 손으로 쓰는 모바일 우선

하단 시트와 페이지 전체 스크롤로 아이폰 Safari의 상태 표시줄·하단 막대까지 자연스럽게 이어지도록 조정

누르면 바로 반영되는 반응

일정 추가·삭제는 서버 응답을 기다리지 않고 화면에 먼저 반영, 검색은 먼저 도착한 결과부터 표시

틀릴 수 있는 정보는 만들지 않음

영업시간처럼 틀리면 곤란한 정보는 직접 제공하지 않고, 사용자가 이미 신뢰하는 지도 앱으로 연결
